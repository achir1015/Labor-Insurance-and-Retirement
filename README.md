**系統功能總結**

**這是什麼**：一份單一 HTML 檔案的個人勞保／國保／勞退查詢系統，資料存在你自己的 Firebase 帳號下（Email/密碼登入 + Firestore 雲端資料庫），只有你自己看得到、改得到。

**主要功能（依導覽列順序）**

| 頁面 | 功能 |
| --- | --- |
| 總覽 | 顯示姓名、投保年資（有填官方數字就優先顯示官方數字，否則顯示「簡易估算，僅供參考」）、勞退專戶累計金額等重點摘要 |
| 勞保／就保記錄 | 逐筆列出投保單位、勞就保投保薪資、災保投保薪資、生效／退保日期等，可搜尋 |
| 國保記錄 | 納保／退保事件記錄 |
| 勞退個人專戶 | 提繳異動紀錄（雇主提繳率、個人自願提繳率、月提繳工資變動）+ 帳戶累計金額 |
| 資料轉換小工具 | 把從勞保局網站複製的表格資料（Tab 分隔）貼上，自動轉成系統要的 XML 格式，可下載或直接匯入 |
| 逐月投保薪資資料庫 | 用「勞保／就保記錄」自動補足成連續月份資料，算出全職涯最高 60 個月投保薪資平均值（老年給付計算用），並可分頁看完整逐月清單 |
| 老年給付試算 | 依官方三種方式（年金月領／一次金／一次請領）試算老年給付金額 |
| 使用說明 | 操作說明 |

**資料怎麼進來 /** **存起來**

-   **匯入**：選擇 XML 檔案，或用「資料轉換小工具」貼表格轉出 XML
-   **儲存**：按「儲存到雲端」寫入 Firestore；「逐月投保薪資資料庫」重建後會**自動**存檔
-   **安全網（今天新增）**：只要畫面有未存檔的變動，切到背景分頁或分頁即將被瀏覽器收掉時會自動存一次，避免瀏覽器省資源機制把分頁重新整理掉時資料不見

**注意事項** **⚠️**

1.  **目前是用 file://** **本機檔案開啟**，不是部署在網址上——瀏覽器對長時間閒置的本機分頁比較容易做記憶體回收（畫面「不定期重新整理」的主因），若想更穩定，可以考慮部署到 Firebase Hosting。
2.  **「總覽」的投保年資如果沒填官方數字，只是系統自己粗略估算**，跟勞保局公告的正式年資可能有出入（因為早期資料的退保日期常是空白，系統無法準確抓出職涯中的空窗期）。
3.  **逐月投保薪資資料庫**是用你系統裡「勞保／就保記錄」的資料自動補出來的連續月份，每次重建都會先清掉舊的再重新產生——如果原始記錄有誤，逐月資料也會跟著錯，請先確認勞保記錄正確再建立。
4.  **老年給付試算是估算工具**，實際金額仍以勞保局正式核定為準，尤其如果你有 98 年（2009 年）以前的投保年資，方式三（一次請領）的資格判斷比較複雜，建議搭配官方試算或親自去電/臨櫃確認。
5.  Firebase 設定（API Key 等）直接寫在 HTML 裡是正常的（Web 端 Firebase 設計如此），真正的存取控制是靠 Firestore 的安全規則（只有登入者本人的 uid 能讀寫自己的資料），不是靠隱藏這組設定值。
6.  這是**你個人專用**的系統，帳號密碼、XML 檔案請自行妥善保管，不要分享給別人。
